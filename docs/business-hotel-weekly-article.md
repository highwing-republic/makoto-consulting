# ビジネスホテル料金トレンド 週次記事（note）の書き方

毎週月曜に、ビジネスホテル料金トレンドの「週次データパック」から note 記事の下書きを作る。
数字は仕組み（ページと同じ集計）で出し、文章は Claude が書き、最後に人が確認・加筆して投稿する。

## 流れ

1. `node scripts/build_business_hotel_weekly.cjs --out <作業用ファイル>` でデータパック（Markdown）を作る。
2. データパックだけを材料に、下の構成で下書きを書く（Claude Docs のドキュメントとして作る）。
3. 人が内容を確かめ、【現場の一言】を書き足して note に投稿する。

## 読み手と文体

- 読み手: ホテル・旅館の経営者、支配人、レベニュー（料金）担当。忙しいので、最初の数行で要点が分かるようにする。
- です・ます調。専門用語は最小限にし、使うときは一言で説明する。
- 長さ: 1,500〜2,500字。
- 煽らない。「〜と見られます」「〜が重なっています」のように、データで言えることだけを書く。

## 構成

1. **タイトル**: 「ビジネスホテル料金ウォッチ（M/D週）｜<今週いちばん目立つ動きを一言>」
2. **リード（3行）**: 今週のポイントを3つ、箇条書きで。
3. **全国の様子**: 10都市の代表料金、最も高い・安い都市、休前日の差、7日前との比較（比較できる週のみ）。
4. **都市別の動き**: 目立つ都市を2〜4都市取り上げる（値動き・急騰日・売り切れ）。全都市は表で一覧にしてもよい。
5. **来週・再来週の注目日**: 急騰日・売り切れが目立つ日を日付順に。重なる催しがあれば「〜が重なっています（参考）」と添える。
6. **宿泊施設が見ておきたい点**: データから言える範囲で2〜3点（例: 「平日でも売り切れが目立つ日がある都市は、直前の料金を見直す余地がないか確認を」）。断定や個別の料金提案はしない。
7. **【現場の一言】**: 空欄の見出しだけ置く（人が書く）。
8. **結び**: ページへのリンク（https://lab.ugatta-llc.com/business-hotel-price-trends.html）と、
   「データ: 楽天トラベル空室検索API（Supported by Rakuten Developers）。大人1名・1室・1泊の最安プラン、各都市のビジネスホテル5施設の中央値。」

## 守ること

- 数字はデータパックの値だけを使う。新しく計算した数字や、丸め直した数字を作らない。
- 「売り切れ」は楽天トラベルで大人1名・1泊のプランが無いことで、施設全体の満室とは書かない。
- 催しは「重なる」「参考」にとどめ、料金が上がった理由と断定しない。取り上げる催しは、出典ページで開催日を確かめてから書く。
- 7日前との比較は同じ宿泊日の料金の比較で、需要が増えた・減ったとは書かない。
- 特定の施設を名指しで評価しない（施設名を出すときはランキングの事実だけにする）。
- データパックで「比較できない」「該当なし」の項目は、無理に書かない。
