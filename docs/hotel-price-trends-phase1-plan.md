# 宿泊料金トレンド Phase 1 実装計画

作成日: 2026-09-29

状態: 実装・検証済み。結果と制限は [検証・引継ぎ](hotel-price-trends-phase1-results.md) を参照。

## 1. 目的と範囲

旅館経営者が、指定宿泊日の公開料金・選択施設の位置・比較データの範囲を短時間で把握できるようにする。事前レビューの修正方針についてユーザーの承認を受け、本計画を作成してから実装する。

既存JSON、取得方式、地域・施設・宿泊日・食事条件、URLパラメータ、料金推移、評価・評価推移・口コミを維持する。新API、スクレイピング、価格推奨、需要・稼働推定、類似施設分類、保存データの拡張は行わない。コミット・push・公開は含めない。

## 3. 指標の可否

| 指標 | 現データでの可否 | 方針 |
|---|---|---|
| 対象施設の中央値 | 可 | 有効料金から算出、3施設未満は参考表示 |
| 選択施設料金 | 可 | 有効料金がなければ「料金未確認」 |
| 対象中央値との差 | 条件付き可 | 有効料金3施設以上かつ選択施設料金あり |
| 料金確認施設数 / 対象数 | 可 | 指定条件の確認件数、満室・在庫とは表現しない |
| 7日前中央値・選択施設料金 | 現在欠損 | 将来の既存形式の履歴に対応、現在は比較データなし |
| 7日前料金確認数 | 現在欠損 | 正確な7日前・比較条件一致時のみ |
| 価格順位 | 条件付き可 | 有効料金3施設以上、同額順位を定義 |
| 取得日 | 可 | snapshot_dateを表示 |
| データ生成日時 | 可 | generated_atをJSTで表示。API取得時刻とは呼ばない |
| 施設別の正確な取得時刻 | 不可 | 作成・推定しない |

## 4. 確定する計算・表示仕様

### 4.1 母集団と有効料金

- 母集団は選択地域の `properties`。地域全施設・競合全施設を代表するとは述べない。
- 指定宿泊日・食事条件に一致し、statusがsuccess、料金が有限の正の数のデータを採用する。
- 1施設1料金として件数・中央値・順位をそろえる。不明な施設や重複行で件数を水増ししない。
- statusがエラー・no_plan・未取得の場合は、残存する料金値を有効値として使わない。
- 指定条件の観測行自体がない状態と、行はあるが成功が0件の状態を区別する。
- 中央値の丸め方は既存仕様を維持。サンプル1〜2施設の中央値も参考値として残す。
- 選択施設しか料金がないとき、地域差0%・市場並み・価格順位を主要KPIやInsightで示さない。

### 4.2 7日前比較

- 基準日は最新スナップショットのsnapshot_date。その7日前と完全一致する履歴を検索する。配列の7件前や直近の日付では代用しない。
- 地域、宿泊日、食事、adults、rooms、nightsが一致し、比較条件が判明していることを必要条件とする。
- 両日の対象施設ID集合が一致しない場合、地域中央値・件数の7日前比較は出さない。
- 地域中央値の増減は両日の料金確認数が3施設以上の場合のみ表示する。
- 確認できた施設の入れ替わりで中央値が変わり得ることを注記する。同じ施設・同じプランの値上げとは断定しない。
- 選択施設自身の7日前料金比較は、同一施設・同一検索条件で両料金が有効なら表示可能。地域サンプル不足とは分ける。
- 履歴ファイル取得失敗、地域不在、条件欠損、該当行不在は欠損扱い。現在の集計表示は維持する。
- 最新データを履歴にも確実に含め、同日の二重読込・履歴欠落による基準日ずれを避ける。

### 4.3 KPI

最大6枚。PCは3列、スマートフォンは1〜2列。

1. 対象施設の中央値（金額、料金確認件数、少数時は参考表示）
2. 選択施設の料金（金額、可能なら7日前金額）
3. 対象中央値との差（`(self / median - 1) * 100`、比較不足時は理由）
4. 中央値の7日前比（条件成立時のみ数値。それ以外は比較データなし等）
5. 価格順位（算出可能時のみカード表示。「料金確認N施設中、高い方からR番目」）
6. 料金確認（確認数 / 対象数。未確認を満室としない）

順位は「自施設より高い施設数 + 1」の競技順位。同額施設が複数あれば「同額」と表示。分母は料金確認施設数。「高価格側○%」は採用しない。

地域差の区分は+10%以上が高い、-10%以下が低い、その間が付近。カレンダーにも同じ境界を適用する。割高・割安・適正価格とは呼ばない。

増減は小数第1位、丸めて0になる値は符号なし0.0%。無効数値、NaN、Infinity、undefined、負のゼロを出さない。金額は円・桁区切り。

### 4.4 DATA INSIGHT

- 旧makeProfileInsights・保存JSON内文章・旧フォールバックの合成をやめ、現在の検証済み集計値から固定テンプレートで最大3文を作る。
- 順番は対象中央値の7日前変化、選択施設の位置、料金確認数。条件が成立しない解釈は省略する。
- 3施設未満は比較不足の説明と確認数を中心にし、「市場並み」と述べない。
- 上昇・低下は数値を添える。±3%、±10%の境界を元計画どおり扱う。
- 「料金データだけでは需要や稼働状況は判断できません。自施設の予約状況とあわせてご確認ください。」を固定表示。
- 根拠が不明な信頼度ラベルは表示しない。評価・口コミそのものの表示機能は維持する。

### 4.5 画面と日付

- TODAY'S MARKET / 今日の市場は採用せず、MARKET SNAPSHOT / 選択した宿泊日の料金状況とする。
- KPI付近に地域・選択施設・宿泊日・食事・大人2名1室1泊・取得日を明示。料金は各施設の指定条件の最低料金、客室・プラン内容までは同一でないと説明する。
- generated_atは有効なタイムゾーン付き日時の場合だけ「データ生成日時（日本時間）」として表示する。現在時刻による代用は禁止。
- 順序は条件、比較範囲、KPI、Insight、料金推移、30日カレンダー、価格ポジション、施設情報、評価、評価推移、口コミ、見方。
- MARKET MOVEMENTのタイトルは「同じ宿泊日の価格変化」。比較可能なら7日前と現在の小さな補助表示を追加。第2軸は追加しない。
- 30日カレンダーに曜日・選択施設料金・対象中央値・対象との差を表示。少数時は比較不足と明示する。
- YYYY-MM-DDを年月日に分けて扱い、曜日が端末のタイムゾーンでずれないようにする。実装では明示的なUTCの生成・曜日取得を一貫して使ってもよい。
- 価格ポジションは既存バーを維持し、選択施設は色に加えて文字でも識別する。
- DOM順と視覚順を一致させ、色だけで状態を伝えない。KPIは横スクロール不要。既存グラフの内部スクロールは許容する。
